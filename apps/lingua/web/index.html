Your key never leaves the browser. The MaaS API key is stored in this browser's localStorage only. Nothing is stored server-side: Lingua is a zero-dependency static PWA. The only network traffic is the OCR and translate calls you initiate, sent to the gateway you configure.

How it works

  • Screen-read, not hooked. Teams has no public caption API, so Lingua captures the pixels of the caption strip via getDisplayMedia and crops them down to 640 px wide before OCR (smaller images are markedly faster).
  • Change detection. every frame is reduced to a 64-px-wide perceptual hash; when the hash matches the previous frame, OCR + translate are skipped entirely, so an idle caption strip costs nothing.
  • Two-stage pipeline. OCR (DeepSeek-OCR-2) runs first, then a non-streaming translation call to the configured chat model. The translation system prompt asks for the target language and nothing else, so the model output is the translation directly.
  • Live last-line. the pipeline marks the last (still-growing) caption line as live, re-translates it as more words arrive, and memoises translations so an identical line is sent to the model exactly once.
  • Speaker-aware. a short capitalised name plate (e.g. "Alice Chen") is detected heuristically and used as the speaker label of the following line, so names are shown once, not twice.
  • Running transcript. a transcript accumulator keeps every line seen, so captions that scroll off the strip stay in the overlay until you clear it.

Constraints

  • Browser screen capture is only available on desktop browsers. The mobile build uses paste / upload instead.
  • Mixed content: browsers refuse to call an http:// gateway from an https:// page. If you host this page over HTTPS, either host the gateway over HTTPS too, or run the page on http://localhost.
  • CORS: the gateway must allow your page's origin. If you see "Blocked by CORS", ask the gateway operator to add your origin to Access-Control-Allow-Origin.
